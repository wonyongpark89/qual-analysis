# Qualitative Coding Workbook

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Students learning qualitative analysis in EDUC6530 Data Analysis for Educational Research at Southampton Education School, and their instructor.

## Product Purpose

Teach the sequence of coding a transcript, developing categories, testing categories against extracts, and developing a theme. The user has confirmed that making the step-by-step learning path clearer is the redesign's priority.

## Operating Context

The workbook is used for teaching. Students enter their name, work with two practice transcripts and three worked examples, and submit work for instructor review. The second transcript is unlocked with an in-class code.

## Capabilities and Constraints

Preserve transcript and instructional content, text selection and code labels, local progress, stage gates, draggable categories, category testing, theme writing, printing, text exports, cloud submissions, instructor verification, synchronization, and comparison. Keep the static single-page deployment and existing Apps Script API contract. Do not submit test data to the production service.

## Brand Commitments

Keep the workbook name, Southampton Education School attribution, and course identity. The user requests a design that is easy to follow and feels less AI generated.

## Evidence on Hand

`index.html` contains the real transcripts, definitions, worked examples, teaching scaffolds, and application behavior. `apps-script/Code.gs` contains the server integration.

## Product Principles

- Show the learning sequence and current task clearly.
- Keep reading and analysis at the center of the interface.
- Preserve existing functionality and student progress compatibility.
- Use purposeful typography, spacing, and controls; avoid decorative dashboard conventions.
